### 2.3 权限评估

**✅ 符合最小权限原则的情况**:
- dev_user 不是 superuser
- dev_user 不能创建数据库
- dev_user 不能绕过 Row Level Security
- 权限仅限于 dev_schema 和 shared schema 的指定表

**⚠️ 改进建议**:
- dev_user 对 dev_schema 表的 TRIGGER 权限可能超出需求（除非有触发器操作）

- 建议将 TRUNCATE/TRIGGER 权限移除，仅保留 CRUD

**风险评估**: 🟢 低风险 — 当前权限配置基本合理，无越权风险

## 四、OpenClaw 配置安全审查

| GATEWAY_AUTH_TOKEN | 2 | 环境变量 | ⚠️ 明文存储 |
| DB 密码 | 1 | 环境变量 + 配置引用 | ✅ 间接引用 |

**评估**: 
- 环境变量存储是 OpenClaw 的标准做法，可接受
- 关键风险点在于进程暴露 (`/proc/<pid>/environ`) 和日志泄露
- 当前无已知泄露路径

### 4.2 配置文件审查

#### `.dev-config.json`
- ✅ 密码不直接存储，使用 `env_var_password` 引用环境变量
- ⚠️ 文件权限为 `644` (world-readable)，建议改为 `600`
- ✅ 内容不含敏感信息

#### `config.yaml` (OpenClaw 主配置)
- 未直接暴露 API Key/Secret（使用环境变量）
- ✅ 符合安全最佳实践

### 4.3 端口暴露检查

## 五、安全事件响应 Playbook

### 5.1 场景 1: 数据库凭证泄露

**触发条件**: 发现异常数据库连接或数据导出

**响应步骤**:
1. 立即修改 `DEV_DB_PASS` 环境变量
2. 重启受影响的服务
3. 审查 PostgreSQL 日志 (`pg_log`) 识别异常操作
4. 更新 `.dev-config.json` 中的密码引用
5. 通知创始人

### 5.2 场景 2: 飞书应用凭证泄露

**触发条件**: 发现异常飞书 API 调用

**响应步骤**:
1. 在飞书开放平台吊销泄露的 App Secret
2. 生成新的 App Secret
3. 更新 `FEISHU_APP_SECRET` 环境变量
4. 审查飞书 API 日志识别异常操作
5. 通知创始人

### 5.3 场景 3: API Key 泄露

**触发条件**: 发现异常 API 调用或计费异常

**响应步骤**:
1. 在对应平台（OpenAI/阿里/智谱等）吊销泄露的 Key
2. 生成新的 API Key
3. 更新对应环境变量
4. 审查 API 调用日志
5. 通知创始人

### 5.4 场景 4: 容器逃逸/未授权访问

**触发条件**: 发现容器内异常进程或文件修改

**响应步骤**:
1. 隔离容器（停止网络访问）
2. 保存容器快照用于取证
3. 重启干净容器
4. 审查所有凭证是否需要轮换
5. 通知创始人

### 5.5 场景 5: 数据误删 (TRUNCATE/DROP)

**触发条件**: 数据库表数据突然消失

**响应步骤**:
1. 立即停止所有写入操作
2. 检查 PostgreSQL WAL 日志
3. 从备份恢复数据
4. 审查 dev_user 权限（移除 TRUNCATE）
5. 通知创始人
